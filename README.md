# AutoTone

Учебный проект: сайт, который сам подправляет яркость, контраст и цветность на фото - прямо в браузере, без сервера. Модель обучена на своих данных, экспортирована в TensorFlow.js и работает локально на устройстве пользователя, так что фотографии никуда не отправляются.

Делал в рамках практики - задача была реализовать полный цикл: от обучения модели до рабочего сайта, который можно открыть по ссылке.

**Демо:** https://killerrkittenn.github.io/AutoTone/

## Как это устроено

Загружаешь фото (можно сразу несколько) - оно встаёт в очередь. Модель уменьшает картинку до 160×160, предсказывает три коэффициента (яркость / контраст / цветность) и по ним пересчитывает уже полноразмерное изображение. Результат можно сравнить со слайдером до/после, а если модель предложила не то, что нужно - есть ползунки, чтобы подправить вручную, и это пересчитывается сразу на клиенте, без повторного обращения к модели.

Вся тяжёлая часть (декодирование, инференс, применение фильтра) идёт в отдельном Web Worker, так что страница не подвисает, даже если фото весит прилично.

## Структура репозитория

```
AutoTone/
├── backend/     обучение модели: датасет, тренировка, экспорт в tfjs
└── frontend/    сайт: интерфейс, воркер с моделью, применение коррекции
```

У каждой папки свой README с более подробными инструкциями внутри.

## Быстрый запуск (только сайт, без переобучения модели)

Модель уже обучена и лежит в `frontend/model/`, так что для проверки сайта переобучать ничего не нужно.

```bash
git clone https://github.com/killerrkittenn/AutoTone.git
cd AutoTone/frontend
python -m http.server 8080
```

Открыть `http://localhost:8080` в браузере. Открывать `index.html` двойным кликом не получится - Worker и динамические импорты не работают через `file://`, нужен именно локальный сервер (или просто открыть демо-ссылку выше).

## Если хочется переобучить модель самому

Все шаги - в `backend/README.md`: своя папка с фото → генерация датасета → обучение → проверка → экспорт в `frontend/model/`.

Коротко:
```bash
cd backend
pip install -r requirements.txt
python generate_dataset.py --source ./reference_images --out ./data
python train_model.py --data ./data --epochs 20
bash export_model.sh best_model.h5 ../frontend/model
```

## API сайта

Модуль реализует контракт, который был в задании: постановка задачи, статус, отмена, получение результата плюс событие изменения статуса. Сверх этого добавил ручную донастройку коэффициентов - этого в задании не было, но по ощущениям сильно улучшает удобство.

| Метод / событие | Что делает |
|---|---|
| `submitTask(file)` | ставит фото в очередь, возвращает `taskId` |
| `getTaskStatus(taskId)` | текущий статус и прогресс |
| `cancelTask(taskId)` | прерывает и убирает задачу |
| `getResult(taskId)` | отдаёт готовое изображение (`Blob`) |
| `statuschange` (событие) | срабатывает на каждом шаге пайплайна |
| `getSuggestedCoefficients(taskId)` | коэффициенты, которые предложила модель |
| `renderWithAdjustment(taskId, coeffs)` | пересчёт с новыми коэффициентами без повторного инференса |

Статусы по ходу обработки: `queued → decoding → inference → enhancing → encoding → done`, либо `error` / `cancelled`.

## Требования из задания и как они закрыты

| Требование | Как сделано |
|---|---|
| Работает во всех современных браузерах | Только стандартные Web API (Worker, OffscreenCanvas, createImageBitmap), без сборки и полифилов |
| До 10 МБ суммарного кода | Свой код - единицы КБ, TF.js и HEIC-декодер подтягиваются с CDN по требованию, модель - маленькая CNN, обученная с нуля (не MobileNet и не другой тяжёлый бэкбон) |
| До 15 Мпк | Проверяется явно, при превышении - понятная ошибка, а не зависание |
| Не больше 30 секунд на фото | Таймаут на уровне API, если что-то идёт не так - задача отменяется сама |
| JPG / PNG / HEIC / BMP | JPG/PNG/BMP декодируются нативно, HEIC/HEIF заранее конвертируются в PNG (браузеры кроме Safari не умеют его читать) |
| Не блокирует интерфейс | Вся обработка - в Web Worker |
| Информирует о прогрессе | Событие `statuschange` на каждом шаге |

## Что можно было бы улучшить

- Датасет для обучения был не очень большим (несколько сотен примеров) - с большим количеством исходных фото модель наверняка предсказывала бы точнее.
- OffscreenCanvas в воркере не поддерживается в совсем старых версиях Safari (до 16.4) - для полной подстраховки нужен fallback на обработку в основном потоке.
- Batch-очередь обрабатывает фото по одному, а не параллельно - для нескольких файлов это не быстро, но зато предсказуемо по нагрузке.
